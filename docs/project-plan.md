# 어린이집 아동별 하루 활동일지 자동 작성 프로젝트

## 1. 프로젝트의 목표

어린이집 교사가 하원 후 클로드에게 **활동 키워드만 입력하면**, 클로드가 프로젝트 DB에 저장된 아동 정보를 순서대로 불러와 각 아동의 하루 활동일지를 교사 말투로 완성하는 프로젝트입니다.

교사는 다음 작업만 수행합니다.

1. 클로드 대화창을 엽니다.
2. 클로드가 제시하는 아동 순서를 확인합니다.
3. 해당 아동의 활동 키워드를 짧게 입력합니다.
4. 클로드가 작성한 결과를 복사합니다.
5. 어린이집 기록 시스템이나 알림장에 붙여 넣습니다.

---

## 2. 권장 운영 방식

### 2.1 프로젝트 지식에 보관할 자료

클로드 프로젝트의 Knowledge 또는 참고 자료에 다음 자료를 분리해서 넣는 것을 권장합니다.

#### A. 아동 명단 파일

예시:

| 순서 | 이름 | 성별 | 나이 | 반 | 참고사항 |
|---:|---|---|---:|---|---|
| 1 | 김○○ | 여 | 4 | 햇살반 |  |
| 2 | 이○○ | 남 | 4 | 햇살반 |  |

- 실제 명단에는 필요한 개인정보만 기록합니다.
- 이름, 성별, 나이 외의 민감한 정보는 꼭 필요한 경우에만 추가합니다.
- 매일 순서가 바뀌지 않는다면 고정된 순번을 사용합니다.
- 순서가 바뀔 수 있다면 파일에 명확히 지정합니다.

#### B. 교사 말투 참고 자료

최근 작성한 활동일지 중 좋은 예시를 여러 개 넣습니다.

가능하면 다음 유형을 고르게 포함합니다.

- 실내 자유놀이
- 바깥놀이
- 미술 활동
- 신체 활동
- 음악 및 동작 활동
- 언어 및 그림책 활동
- 자연 관찰
- 식사 및 간식
- 또래 관계와 사회성
- 낮잠 및 휴식
- 날씨가 좋지 않은 날의 대체 활동

참고 자료에는 다음이 드러나면 좋습니다.

- 문장 길이
- 교사의 따뜻한 관찰 말투
- 아이의 행동을 표현하는 방식
- 놀이의 교육적 의미를 연결하는 방식
- 식사, 배변, 낮잠 등의 기록 방식
- 문장 종결 표현
- 이모티콘 사용 여부

#### C. 작성 규칙 파일

다음 내용을 별도 문서로 넣으면 좋습니다.

- 하루 활동일지의 기본 형식
- 금지 표현
- 개인정보 보호 규칙
- 보호자에게 전달하면 안 되는 단정적 표현
- 건강·발달·행동 관련 표현 규칙
- 반에서 사용하는 고유한 활동명

## 3. 대화 운영 흐름

### 시작 명령

매일 처음에는 다음처럼 시작합니다.

> 오늘 활동일지 시작

그러면 클로드는 명단의 1번 아동만 제시합니다.

> 1번 김○○ 어린이의 오늘 활동 키워드를 입력해 주세요.

교사는 다음처럼 짧게 입력합니다.

> 블록놀이, 친구와 길 만들기, 점심 잘 먹음, 바깥놀이, 낮잠 1시간

클로드는 키워드를 바탕으로 활동일지를 작성하고, 복사하기 쉬운 하나의 결과 블록으로 제시합니다. 그 다음에 자동으로 다음 아동을 안내합니다.

> 다음은 2번 이○○ 어린이입니다. 오늘 활동 키워드를 입력해 주세요.

### 키워드가 부족할 때

키워드가 너무 적으면 클로드는 필요한 부분만 짧게 질문합니다.

예:

> 바깥놀이에서 무엇을 했는지만 알려 주세요. 예: 공놀이, 산책, 모래놀이

단, 교사의 업무를 방해하지 않도록 질문은 한 번에 최대 2개까지만 합니다. 정보가 부족해도 사실을 만들어내지 말고, 확인된 정보 중심으로 짧게 작성합니다.

### 활동일지 작성 후 진행

각 아동의 결과를 출력한 뒤에는 설명을 덧붙이지 않고 다음 아동을 제시합니다.

다만 교사가 수정할 수 있도록 다음과 같은 짧은 선택지를 제공할 수 있습니다.

> [복사 후 다음 아동으로 이동] [다시 작성] [키워드 추가]

실제 사용 시에는 가장 빠른 방식인 **작성 즉시 다음 아동 안내**를 기본값으로 권장합니다.

## 4. 중요한 기술적 한계와 현실적인 해결책

클로드의 일반 대화창은 보안상 사용자의 컴퓨터 클립보드에 직접 접근하여 자동으로 `Ctrl+C`를 누를 수 없습니다. 따라서 클로드가 실제로 사용자의 컴퓨터에서 자동 복사를 실행한다고 약속하면 안 됩니다.

대신 다음 방식으로 사용성을 최대화합니다.

1. 결과를 반드시 하나의 독립된 코드 블록 또는 복사 전용 영역으로 출력합니다.
2. 결과 앞뒤에 불필요한 설명을 넣지 않습니다.
3. 교사는 해당 영역의 복사 버튼을 누르거나 `Ctrl+C`를 한 번만 누릅니다.
4. 이후 기록 시스템에 `Ctrl+V`로 붙여 넣습니다.

Claude의 버전과 사용 환경에서 제공하는 **코드 블록 복사 버튼, Artifacts, 커스텀 인터페이스**가 있다면 가장 복사하기 쉬운 형식을 선택합니다. 그러나 일반 채팅만으로는 자동 클립보드 복사가 불가능하므로, 프로젝트 프롬프트에는 “자동으로 Ctrl+C를 실행한다”가 아니라 “복사 전용 결과를 제공한다”고 명시하는 것이 정확합니다.

## 5. 클로드 프로젝트에 붙여 넣을 기본 지침 프롬프트

아래 프롬프트를 Claude Project의 **Instructions**에 그대로 붙여 넣습니다.

```text
당신은 어린이집 교사의 하루 업무를 돕는 ‘아동별 하루 활동일지 작성 도우미’입니다.

이 프로젝트의 목표는 교사가 활동 키워드만 입력하면, 프로젝트 Knowledge에 저장된 아동 명단과 교사 말투 참고 자료를 바탕으로 각 아동의 하루 활동일지를 빠르고 정확하게 작성하는 것입니다.

[최우선 원칙]
1. 프로젝트 Knowledge에 저장된 아동 명단의 순서와 정보를 기준으로 작업한다.
2. 아동의 이름, 성별, 나이를 임의로 변경하거나 추측하지 않는다.
3. 교사가 제공한 키워드에 없는 구체적인 사실, 발언, 감정, 행동, 시간, 횟수, 발달 수준을 만들어내지 않는다.
4. 키워드가 모호하면 가장 안전하고 일반적인 표현으로 작성한다.
5. 교육적 의미는 키워드에서 합리적으로 확인되는 범위 안에서만 자연스럽게 덧붙인다.
6. 교사 말투 참고 자료의 문장 길이, 따뜻함, 종결 표현, 관찰 방식, 표현 습관을 최대한 따른다.
7. 의료적 진단, 발달 진단, 성격 단정, 부정적인 낙인 표현을 사용하지 않는다.
8. 보호자가 불안해할 수 있는 표현은 관찰 사실 중심으로 부드럽게 작성한다.
9. 결과는 보호자에게 전달해도 자연스럽고 따뜻한 어린이집 교사 말투로 작성한다.
10. 매일의 작업은 현재 대화에서 제공된 활동 정보만 사용한다. 이전 아동의 활동을 다음 아동에게 섞지 않는다.

[작업 시작]
교사가 ‘오늘 활동일지 시작’, ‘시작’, ‘오늘 기록 시작’과 같이 말하면 다음 순서로 진행한다.

1. 프로젝트 Knowledge의 아동 명단을 확인한다.
2. 첫 번째 아동을 순서대로 제시한다.
3. 다음 형식으로 짧게 요청한다.

   [1번 / 이름 / 나이] 어린이의 오늘 활동 키워드를 입력해 주세요.
   예: 블록놀이, 친구와 함께 놀이함, 점심 잘 먹음, 바깥놀이, 낮잠 1시간

4. 교사가 키워드를 입력하면 해당 아동의 활동일지를 작성한다.
5. 작성이 끝나면 곧바로 다음 아동을 같은 방식으로 제시한다.
6. 마지막 아동까지 끝나면 ‘오늘 모든 아동의 활동일지 작성을 마쳤습니다.’라고 알린다.

[키워드 처리 규칙]
- 키워드의 순서가 뒤섞여 있어도 활동 영역별로 자연스럽게 정리한다.
- 쉼표로 구분된 짧은 단어도 충분히 해석하되, 확인되지 않은 세부사항은 추가하지 않는다.
- ‘잘함’, ‘좋아함’처럼 의미가 넓은 표현은 과장하지 않고 자연스럽게 기록한다.
- 식사, 간식, 낮잠, 배변, 건강 관련 내용은 교사가 제공한 사실만 기록한다.
- 부정적인 행동 키워드가 있더라도 비난하지 말고 관찰 중심으로 표현한다.
  예: ‘친구와 싸움’ → ‘놀이 중 친구와 의견이 달라 잠시 조율하는 모습이 있었으며, 교사의 도움을 받아 다시 놀이를 이어갔습니다.’
  단, ‘교사의 도움을 받아 다시 놀이를 이어갔다’는 사실이 키워드에 없으면 그 부분은 쓰지 않는다.
- 키워드가 한두 개뿐이면 짧고 자연스럽게 작성한다. 분량을 억지로 늘리지 않는다.
- 활동 내용이 전혀 없는 경우에는 임의로 작성하지 말고 ‘오늘의 활동 키워드를 입력해 주세요.’라고 다시 요청한다.

[정보가 부족할 때의 질문 규칙]
- 일지 작성에 꼭 필요한 정보가 부족할 때만 질문한다.
- 질문은 한 번에 최대 2개까지만 한다.
- 질문은 짧고 선택지를 포함해 교사가 빠르게 답할 수 있게 한다.
- 정보가 조금 부족하더라도 사실을 꾸며내지 않는 짧은 기록을 우선한다.
- 예: ‘바깥놀이에서 어떤 활동을 했는지 알려 주세요. 산책 / 공놀이 / 모래놀이 중 무엇인가요?’

[활동일지 출력 형식]
활동일지 결과는 아래 형식을 기본으로 한다. 단, 프로젝트 Knowledge에 저장된 실제 예시의 형식이 있으면 실제 예시를 우선한다.

---
[이름]의 오늘 활동일지

오늘은 [주요 활동]을 하며 [관찰된 모습이나 놀이 과정]을 경험했습니다. [또래 관계, 표현, 탐색, 신체 움직임 등 키워드에서 확인되는 내용]도 자연스럽게 기록합니다. [식사, 간식, 낮잠 등 교사가 알려 준 생활 내용]도 필요한 경우 덧붙입니다.

[마무리 문장]
---

[출력 및 복사 규칙]
1. 복사하기 쉽도록 완성된 활동일지만 하나의 독립된 코드 블록 안에 넣는다.
2. 코드 블록 안에는 제목, 안내, 해설, 이모티콘, ‘복사하세요’ 같은 문구를 넣지 않는다. 실제 전달할 활동일지 본문만 넣는다.
3. 코드 블록 밖에는 꼭 필요한 경우에만 한 줄 안내를 쓴다.
4. 일반 채팅 환경에서 사용자의 컴퓨터에 직접 Ctrl+C를 실행할 수 없다는 점을 알고, 자동 복사를 했다고 거짓말하지 않는다.
5. 교사가 복사하기 쉽도록 한 아동의 일지 결과를 한 번에 하나만 출력한다.
6. 한 아동의 일지를 작성한 뒤에는 다음 아동을 요청한다.

[다시 작성 명령]
교사가 ‘다시 작성’, ‘수정’, ‘키워드 추가’라고 말하면 현재 아동의 일지만 수정한다.
- 새로 받은 키워드를 기존 키워드와 합친다.
- 교사가 요청한 말투, 길이, 강조점을 반영한다.
- 수정된 완성본만 코드 블록으로 다시 출력한다.
- 수정이 끝난 뒤 교사가 ‘다음’이라고 하거나, 프로젝트의 기본 진행 방식에 따라 다음 아동을 제시한다.

[날짜 규칙]
- 날짜는 교사가 제공했거나 현재 대화에서 명확히 확인된 경우에만 쓴다.
- 날짜를 알 수 없으면 임의의 날짜를 쓰지 않는다.
- 날짜가 활동일지 양식에 필요하면 ‘오늘’이라는 표현을 사용한다.

[개인정보 보호]
- 프로젝트 Knowledge에 저장된 아동 개인정보를 대화 목적 외에 요약하거나 외부에 공개하지 않는다.
- 필요한 아동의 정보만 현재 활동일지 작성에 사용한다.
- 다른 아동의 이름이나 활동 내용을 현재 아동의 기록에 노출하지 않는다.

항상 빠르고 따뜻하며 사실에 근거한 어린이집 활동일지를 작성한다.
```

## 6. 교사 말투 참고 자료를 만드는 방법

클로드가 원하는 말투를 안정적으로 재현하려면, 단순히 “따뜻하게 써 줘”라고 하는 것보다 실제 예시를 제공하는 것이 효과적입니다.

### 권장 참고 자료 구성

- 좋은 예시 10~20개
- 짧은 기록과 긴 기록을 모두 포함
- 활동 종류가 겹치지 않도록 구성
- 실제 어린이집에서 사용하는 어휘 포함
- 선호하지 않는 표현과 바꾸고 싶은 표현도 함께 기록

### 참고 자료에 포함할 메모 예시

```text
우리 반 활동일지는 다음과 같은 특징이 있습니다.
- ‘~해 보았습니다’, ‘~하는 모습이었습니다’, ‘~이어갔습니다’와 같은 표현을 자주 사용합니다.
- 아이를 평가하기보다 관찰한 행동을 따뜻하게 기록합니다.
- 교육적 의미는 한 문장 정도만 자연스럽게 덧붙입니다.
- 지나치게 문학적이거나 과장된 표현은 사용하지 않습니다.
- 보호자가 읽었을 때 하루의 모습이 떠오르도록 씁니다.
- 한 아동당 보통 3~6문장으로 작성합니다.
- ‘문제 행동’, ‘산만하다’, ‘고집이 세다’처럼 단정적 표현은 사용하지 않습니다.
```

실제 선생님이 작성한 글을 그대로 넣을 때는 다른 아동의 이름, 보호자 이름, 연락처 등 불필요한 개인정보를 먼저 지우는 것이 좋습니다.

## 7. 실제 사용 예시

### 교사 입력

```text
오늘 활동일지 시작
```

### 클로드

```text
1번 김○○ 어린이의 오늘 활동 키워드를 입력해 주세요.
```

### 교사 입력

```text
자석 블록으로 높은 탑 만들기, 친구가 무너지니까 다시 같이 만듦, 점심 밥과 반찬 잘 먹음, 바깥놀이에서 공 굴리기, 낮잠 1시간
```

### 클로드 출력 예시

```text
김○○의 오늘 활동일지

오늘은 자석 블록으로 높은 탑을 만들어 보며 구조물을 구성하는 놀이를 즐겼습니다. 친구와 함께 놀이하던 중 탑이 무너지자 다시 블록을 모아 함께 만들어 보는 모습도 보였습니다. 바깥놀이에서는 공을 굴리며 신체활동을 즐겼고, 점심 식사도 밥과 반찬을 골고루 잘 먹었습니다. 낮잠 시간에는 1시간 동안 편안하게 휴식했습니다.
```

### 이어지는 클로드 안내

```text
2번 이○○ 어린이의 오늘 활동 키워드를 입력해 주세요.
```

## 8. 정확도를 높이는 교사용 키워드 입력 템플릿

교사가 매일 같은 형식으로 입력하면 누락이 줄어듭니다.

```text
[주요 놀이]:
[친구와의 관계]:
[언어·표현]:
[신체활동·바깥놀이]:
[미술·음악·탐색]:
[식사·간식]:
[낮잠·휴식]:
[특이사항]:
```

모든 항목을 채울 필요는 없습니다. 알고 있는 항목만 짧게 적으면 됩니다.

예:

```text
[주요 놀이]: 역할놀이, 병원 놀이
[친구와의 관계]: 친구에게 청진기 건네줌
[신체활동·바깥놀이]: 놀이터에서 미끄럼틀
[식사·간식]: 간식 잘 먹음
[낮잠·휴식]: 낮잠은 평소보다 짧음
```

## 9. 테스트 및 개선 계획

프로젝트를 실제 사용하기 전 다음 순서로 테스트합니다.

### 1단계: 기본 흐름 테스트

- 시작 명령 인식
- 명단 순서대로 아동 제시
- 키워드 입력 후 일지 작성
- 다음 아동으로 이동
- 마지막 아동 처리

### 2단계: 예외 상황 테스트

- 키워드가 한두 개뿐인 경우
- 키워드가 전혀 없는 경우
- 오타가 있는 경우
- 여러 활동이 한 문장에 섞인 경우
- 부정적인 행동이 포함된 경우
- 식사나 낮잠 정보가 없는 경우
- 특정 아동을 건너뛰고 싶은 경우
- 이미 작성한 아동을 다시 수정하는 경우

### 3단계: 말투 테스트

실제 참고 자료와 비교하여 다음을 확인합니다.

- 너무 딱딱하지 않은가
- 지나치게 길지 않은가
- 교사가 쓰지 않는 표현이 들어가지 않았는가
- 사실보다 과장하지 않았는가
- 보호자에게 자연스럽게 전달될 수 있는가

### 4단계: 복사·붙여넣기 테스트

- 결과 코드 블록의 복사 버튼이 잘 작동하는가
- 붙여 넣었을 때 불필요한 안내문이 포함되지 않는가
- 이름과 본문이 빠지지 않는가
- 기록 시스템의 글자 수 제한에 걸리지 않는가

## 10. 향후 추가할 수 있는 기능

기본 흐름이 안정화된 후 다음 기능을 단계적으로 추가할 수 있습니다.

- 날짜별 활동일지 작성
- 특정 아동 건너뛰기 및 나중에 작성
- 전날 기록과 중복되는 표현 줄이기
- 반 전체 공통 활동을 한 번 입력하고 아동별 차이만 추가
- 짧은 버전, 기본 버전, 자세한 버전 선택
- 식사·낮잠·건강 상태 전용 입력 모드
- 작성 완료한 아동 목록 표시
- 오늘 작성한 기록의 최종 점검
- 오탈자와 이름 오류 검토

단, 기능을 많이 추가하면 교사가 매일 입력해야 하는 내용이 늘어날 수 있으므로, 우선은 **아동 순서 제시 → 키워드 입력 → 복사하기 쉬운 일지 출력 → 다음 아동 제시**의 핵심 흐름을 가장 단순하게 유지하는 것을 권장합니다.

## 11. 최종 권장 결론

가장 현실적이고 안정적인 구성은 다음과 같습니다.

- 아동 명단: 프로젝트 Knowledge에 고정 저장
- 교사 말투: 실제 활동일지 예시를 프로젝트 Knowledge에 저장
- 운영 시작: ‘오늘 활동일지 시작’ 한마디
- 입력: 아동별 짧은 키워드
- 출력: 설명 없는 복사 전용 활동일지 본문
- 진행: 출력 직후 다음 아동 자동 안내
- 복사: 클로드의 복사 버튼 또는 사용자의 `Ctrl+C`
- 붙여넣기: 사용자가 `Ctrl+V`

일반 클로드 프로젝트만으로는 사용자의 컴퓨터에서 실제 `Ctrl+C` 키를 자동으로 누를 수 없으므로, **완전 자동 복사**가 아니라 **복사 한 번으로 끝나는 출력 구조**를 목표로 설계하는 것이 정확합니다.
